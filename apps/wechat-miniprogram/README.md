# 山海水戏 · 微信原生小程序

这是原生微信小程序，不是 WebView/H5 套壳。当前已迁移九个故事的“山海奇闻目录 → 白话故事/原文竹卷 → 横屏水上戏台”闭环。

## 当前能力

- 主包放首页、九岛目录、五套水幕舞台、共享服务和轻量封面；九个故事分别放进九个分包。
- 九本书封面由各故事最终版 Web 背景、代表人物和道具重新合成，不再共用山水画。
- 每个故事有白话文、带拼音的古文、三幕 1280×720 纯背景，以及独立的透明人物/道具层；角色可由手掌位置连续驱动，不再把人物烘焙在一张 JPG 里。
- 阅读页支持横竖屏；竖屏可左右轻扫查看右侧人物、道具和完整场景，横屏使用全画面构图。
- 阅读页有显眼的“横屏观看”入口；横屏页进入水戏时不再重复弹出方向提示。
- 水上戏台仅在横屏开启。左下角是前置摄像头与 21 点手部骨架，右下角只显示“请操作 / 你会看到”，中央舞台不被两个面板遮挡。
- 戏台底部可切换漆木飞檐、竹编水亭、月白石台、彩灯庙台、玉石水门五套水幕，选择会在本机保留。
- 点击“开启摄像头”后，由微信官方 VisionKit `VKSession` 接管摄像头与 WebGL 预览，以实时 `mode: 1` 输出 21 个手部关键点。关键点经时间平滑、捏合迟滞阈值和稳定帧确认后，再驱动剧情。
- 完整动作链路为“手势跟踪 → 角色/道具连续移动 → 剧情动画 → 动画完成 → 下一步”；不再在检测成功时立即跳幕。
- 微信开发者工具的 macOS 模拟器不支持 VisionKit v1；它只验收舞台布局与透明角色图层，并显示“VisionKit 需要真机运行”。摄像头预览、21 点骨架和动作识别必须在真机验收。

## 包体与画质

当前生成结果约为：主包 1.58 MiB；九个故事分包约 1.55–1.85 MiB；轻量真机工程约 2.94 MiB。每个单独包仍低于 2 MiB，同时保留 1280×720 场景与所有故事所需的透明舞台图层。

微信当前分包规则以官方发布工具校验为准：主包与单个分包各不超过 2 MiB；普通小程序全部包合计上限当前为 30 MiB，服务商代开发项目为 20 MiB。参见 [微信官方分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/basic.html)。

## 生成与验证

在项目根目录执行：

```bash
npm run build:miniprogram-stories
npm test
```

第一条命令依据共享故事数据重新生成九个分包及 27 张三幕场景；第二条命令验证九故事/27 幕、119 项故事资产、API、动作时序、人物道具挂点和 Web 回归。

不要手工编辑 `story-packages/` 内的生成文件。页面模板位于 `scripts/miniprogram-story-templates/`，共享逻辑位于 `shared/`。

## 开发者工具与真机

1. 在微信开发者工具中导入本目录 `apps/wechat-miniprogram/`。
2. 使用当前测试 AppID 或正式 AppID 编译。
3. 模拟器可验收目录、阅读、横屏提示、动态水面与分层人物道具；摄像头与 VisionKit 必须使用真机。
4. 点击“预览”或“真机调试”，在支持 VisionKit 的手机微信上验收 21 点骨架、动作稳定保持和自动推进剧情。
5. 首次开启摄像头时允许微信摄像头权限；拒绝后可通过页面的“打开设置”重新授权。

本机 API 默认配置仍在 `services/config.js`。手机上的 `127.0.0.1` 指手机自身；若改回真实 HTTP API，真机必须使用可访问的 HTTPS 服务，并在微信后台配置合法请求域名。小程序不保存 AppSecret。
