# 山海水戏 · 四端迁移清单

更新日期：2026-10-09。本项目是中国《山海经》与越南水傀儡结合的互动故事体验，不是金融项目。

## 当前架构

```text
project/
├── index.html、app.js、*.css…     # 现有 Web
├── stories.js、scene-data.js…    # 九故事、27 幕共享内容源
├── assets/、资料库/、图片库/       # 原始数字资产
├── apps/
│   ├── web/                      # Web 迁入预留
│   ├── ios/                      # iOS 预留
│   ├── android/                  # Android 预留
│   └── wechat-miniprogram/       # 已可编译的原生微信小程序
├── services/backend/             # 共享只读内容 API
├── packages/api-contracts/       # 跨端响应契约
├── scripts/miniprogram-story-templates/
└── tests/
```

目标仍是四个独立客户端使用同一套 HTTPS API；UI、摄像头、渲染与手势输入按平台适配，不复制业务后端。

## 微信端已完成

- 九岛目录与九个故事入口。
- 九本书使用各故事最终版 Web 背景、人物与道具合成的专属封面。
- 九个故事独立分包，每包包含白话/古文阅读、水上戏台和三幕场景。
- 白话与古文共用纯净全画面背景及独立悬浮人物/道具层；古文提供逐字拼音，阅读页不混入舞台特效图层。
- 阅读页横竖屏自适应；竖屏可横向轻扫查看人物、道具与完整场景，并可直接点击“横屏观看”。
- 水上戏台横屏守卫、五套可切换越南水傀儡水幕、左下摄像头、右下“请操作 / 你会看到”指引，中央主舞台保持无遮挡。
- 微信 `<camera>` 权限链路、VisionKit v1 手部识别、21 点/骨骼连线、镜像校正、张掌/握拳/捏合分类。
- 手势稳定保持后按剧情自动推进，水面随动作加强；开发者工具不支持 VisionKit 时只降级为摄像头预览。
- 27 张 1280×720 三幕场景与 Canvas 2D 分层折射水面，不再使用底部二维圆环波纹。

## 分包与资产预算

当前工程约：主包 1.76 MiB，故事分包各 1.65–1.88 MiB，总计约 17.56 MiB。主包和每个分包均低于 2 MiB 上限。

原始 `assets/`、`资料库/`、Blender 工程不整体放进客户端；发布图只放对应故事分包。高分辨率制作文件继续留在资料库，避免主包首启下载和内存压力。

官方当前规则：普通小程序所有包合计不超过 30 MiB，服务商代开发项目不超过 20 MiB，主包或任一分包不超过 2 MiB。发布前仍以当时开发者工具校验和 [微信官方分包文档](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/basic.html) 为准。

## 后端与 API

原 Web 最初没有业务 HTTP API；当前 `services/backend/` 提供共享只读内容接口，契约位于 `packages/api-contracts/`。微信端保留开发/体验/正式环境配置边界，不把 AppSecret、会话密钥或供应商密钥放进客户端。

目前没有账号、支付、交易或金融接口。未来若增加跨端存档，再设计微信登录、用户绑定、数据库和鉴权。

## 继续推进顺序

1. 用微信“真机调试”验收 VisionKit 21 点骨架、摄像头方向、帧率、发热和九故事动作推进。
2. 根据真机结果微调动作阈值、保持时间和低端机画质档位。
3. 配置可公开访问的 HTTPS API/资源域名，完成体验版与隐私说明。
4. 再建立 iOS 与 Android 原生工程，复用内容契约与剧情定义，分别适配相机及手势推理。
5. Web 稳定回归后再决定是否把根目录文件迁入 `apps/web/`，避免提前破坏现有路径。

## 验收命令

```bash
npm run build:miniprogram-stories
npm test
```

自动化覆盖九故事/27 幕、119 项故事资产、API 边界、横屏/摄像头逻辑、剧情动作时序、角色和道具挂点。开发者工具已经完成编译与摄像头预览验收；VisionKit 识别必须在支持该能力的微信真机上做最终验证。
