# 微信真机调试对照测试

本分支用于对照“关闭手势识别后，自动真机调试是否仍然超时”。

- 分支：`test/no-gesture-upload-cache`
- 导入目录：`apps/wechat-miniprogram-diagnostic`
- VisionKit：关闭
- 摄像头权限：不请求
- 素材：保留首页、《精卫填海》和五个水幕
- 上传策略：忽略未使用文件，不上传 Source Map

## 基线数据

- 文件数：54（不含本地 `project.private.config.json`）
- 目录大小：约 3.1MB
- 图片大小：约 2.8MB
- 重复图片：0 组
- 重复文本：2 组（阅读页横竖屏 WXML/WXSS）

## 验证方法

1. 在微信开发者工具中导入上述诊断目录。
2. 确认首页显示“无手势上传测试”标记。
3. 连续执行三次自动真机调试，记录每次从点击到手机打开的时间。
4. 如仍在 `File Analyze Successful` 之后 Timeout，则瓶颈不是 VisionKit 或图片解码，而是上传/调试连接阶段。
5. 如此版稳定、原版不稳定，再分别比较摄像头权限与 VisionKit 会话初始化。

## 关于缓存

小程序上传不提供一个可由项目打开的“重复图片上传缓存”开关。可控的方式是：

- 只把运行时会用到的文件放入代码包。
- 使用主包/分包按需加载。
- 对完全相同的资源只保留一份。
- 开发时启用忽略未使用文件；动态路径资源必须明确保留。
